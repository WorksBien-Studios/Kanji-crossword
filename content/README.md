# Generated puzzle content

The canonical release artifacts are generated by `engine/final_pipeline.py`
and must pass `engine/release_validator.py` before they are committed.

- `puzzles-v2.json` — **360** schema-v2 puzzles with content-addressed IDs.
- `puzzles-v2-sample.json` — five representative records for inspection.
- `manifest.json` — schema version, puzzle ID, mode and SHA-256 validation
  digest for every bundled puzzle.

Schema v1 sequential-ID files are removed by the generator so an app target
cannot accidentally bundle stale content.

Every release puzzle is independently re-solved by the exhaustive CSP solver.
The release gate also checks dimensions, connectivity, one-to-one number/kanji
mapping, exact tray contents, readings, prohibited words, no vocabulary reuse,
solver-derived difficulty metadata, content-addressed IDs and manifest/digest
integrity.

Regenerate and validate with:

```bash
python3 engine/final_pipeline.py --output-dir content
python3 -m unittest discover -s tests -v
```

## Compact library for the YouTube Playables game

`compact/puzzles-compact.json` holds dense **5x5 puzzles** in the classic number-crossword style,
generated by `engine/compact_pipeline.py`: 2- and 3-kanji words, 16-17 cells, and only 7-8 distinct
kanji (an 8-key tray) because a repeated kanji shares one number. Each board is built from a small
cluster of related kanji, every word is checked against the reviewed vocabulary, and every puzzle
is proven uniquely solvable by the independent solver. A word appears in at most two puzzles and
each kanji cluster is used once. 125 further words (war, death, sexual, religious, political,
criminal, gambling and name-like entries) are never shipped on a board, though they still count in
the uniqueness check. Validated by `tests/test_compact.py`; independent of
`puzzles-v2.json` and its manifest. The records are labelled `automated_and_ai_review_pending_owner_approval`: a stricter AI-assisted
word-by-word review, not an editor's sign-off.
